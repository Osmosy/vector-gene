# Шаблон данных пациента (OKF-style)

Каталог показывает структуру, в которой агент читает и ведёт данные. В репозитории
лежат только синтетические примеры — реальные данные пациента сюда не коммитятся.

```
data/patient/
├── SUMMARY.md          # одностраничный обзор
├── HISTORY.md          # медицинская история, таймлайн
├── MEASUREMENTS.md     # показатели и лабораторные результаты во времени
├── MEDS.md             # текущие и прошлые препараты
├── PROBLEMS.md         # активные проблемы здоровья
├── TESTS.md            # результаты обследований
├── VISITS.md           # журнал визитов
├── HYPOTHESES.md       # гипотезы агента к проверке
├── QUESTIONS.md        # вопросы врачу
├── TREATMENT_PLAN.md   # текущий план лечения
├── TODO.md             # следующие шаги
├── genetic/
│   ├── raw/            # FASTQ, VCF, сырые таблицы 23andMe/Genotek
│   ├── variants.md     # отобранные варианты
│   └── analysis.md     # вывод анализа (с указанием, какие навыки задействованы)
├── drugs/
│   └── responses.md    # фармакогенетика: CYP2C9/CYP2C19/VKORC1/CYP4F2 …
└── reports/            # лабораторные отчёты, сканы
```

Правила ведения:

1. В `genetic/analysis.md` каждая находка помечается источником — какой навык и какая
   база дали число (ClinVar / gnomAD / GTEx / AlphaGenome).
2. Отсутствие сигнала — тоже запись: «значимого эффекта не предсказано» пишется
   явно, а не пропускается.
3. Всё, что похоже на вывод о здоровье, идёт в `HYPOTHESES.md` с пометкой
   «требует проверки врачом» — и только там.
